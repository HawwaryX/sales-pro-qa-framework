# استئناف QA الفعلي وانتظار أدوات Android

لا تستنتج نجاح المصادقة أو الأعمال من اكتمال أمر أو worker. المرجع الحالي هو
`reports/sales_pro_e2e_20261017_225758/test_ledger.json` وأدلته. أعد استخدامه؛
لا تعِد تثبيت APK أو تمسح بياناته لمجرد استئناف جلسة.

## الفحص الاختياري المحدود

`scripts/android_login_probe.py` يشغّل فحص UI قبل المصادقة في عملية منفصلة،
بمهلة إجمالية افتراضية 240 ثانية تشمل بدء UIAutomator والانتظار والكتابة.
العملية تستقبل JSON في stdin فقط بمفاتيح `username`, `password`, `branch`, `year`.
لا تضع القيم في argv أو ملف أو سجل أو متغير محفوظ داخل المشروع.
استخدم مجلد أدلة جديدًا لكل محاولة؛ الأداة ترفض استبدال مجلد موجود.

متطلبات هذا الفحص الاختياري: ADB محلي على127.0.0.1:5037 وجهاز اختبار مصرح به
أكمل boot، والتطبيق مثبت مسبقًا. لا يبدأ السكربت محاكيًا أو ADB عامًا.
قبل UIAutomator ينتظر العامل حتى60 ثانية ضمن المهلة الإجمالية: اكتمال boot،
معرّف المستخدم الحالي الصالح وحالته `RUNNING_UNLOCKED`، وحل `MainActivity`
المحدد لذلك المستخدم. `sys.boot_completed=1` وحده لا يكفي أثناء
`RUNNING_UNLOCKING`. تسجل خلاصة الجاهزية فقط دون مخرجات الأوامر؛ لا يحاول
فتح المستخدم أو تغيير القفل. لكل أمر مهلة محدودة بالوقت المتبقي.
يلزم توفر adbutils وuiautomator2 وPillow في بيئة أدوات معزولة، بالإضافة إلى
تثبيت المشروع editable أو ضبط PYTHONPATH إلى src. الإصدارات التي نُفذت هنا:
adbutils2.12.0 وuiautomator2 3.7.0 وPillow13.0.0؛ ليست dependencies للمشروع أو CI.

مثال Python تفاعلي لا يضع القيم في سجل الأوامر؛ شغّله بمفسر بيئة الأدوات:

```python
import getpass
import json
import subprocess
import sys

account = {
    "username": getpass.getpass("اسم حساب الاختبار: "),
    "password": getpass.getpass("كلمة المرور: "),
    "branch": input("الفرع المصرح به: "),
    "year": input("السنة المالية: "),
}
subprocess.run(
    [sys.executable, "scripts/android_login_probe.py",
     "--output", "reports/new-runtime-evidence", "--timeout", "240"],
    input=json.dumps(account), text=True, check=True, timeout=260,
)
```

قائمة الوسائط تدعم مسارات Windows ذات المسافات؛ استخدم `sys.executable`
ومجلد العمل الخاص بالمشروع. المشرف يقتل مجموعة العملية وأبناءها عند المهلة
على POSIX؛ على Windows يقتل العامل المباشر فقط، ولا يضمن إنهاء كل أبنائه.

## ما ينفذه وما تثبته الأدلة

- يدخل الحساب حرفيًا ويتحقق من الإخفاء، ثم يطلب القوائم والحساب مُعبّأ.
- يختار الفرع والسنة بمطابقة كاملة للقيمة الظاهرة؛ لا يحقن معرّفات ولا يختار
  فرعًا افتراضيًا بدل القيمة المطلوبة. إن غاب الاختيار، يسجل الحاجز ولا يرسل
  طلب دخول بإعدادات بديلة.
- يحفظ XML محجوبًا وصورة مقصوصة أسفل حقلي الحساب، ثم يفرغ حقلي النموذج فقط.
  لا clear-data ولا تغيير backend ولا عمليات عملاء أو معاملات.
- `supervision.json`: COMPLETED/FAILED/TIMED_OUT/ERROR نتائج عملية العامل فقط.
  اقرأ `observations.json` و`login_submitted` و`authenticated` قبل تسجيل نتيجة
  وظيفية. لا استنتاج PASS من returncode0.
- `progress.jsonl` يحدد المرحلة وزمنها دون القيم السرية. ملفات الإعداد الخام
  وlogcat الكامل بعد إدخال الحساب لا تحفظ ضمن الأدلة المنشورة.

تجاوز بدء UIAutomator على TCG مهلة المكتبة الافتراضية30 ثانية فعليًا؛ يتيح
العامل90 ثانية لبدء الخدمة مع بقاء السقف الإجمالي240 ثانية. التعديل محلي
للعملية ولا يغير ملفات المكتبة أو APK. انتظار idle محدد بثانية؛ إذا فشل
الرسم تسجل الحالة كما هي، ولا تؤخذ لقطة splash دليلًا لنجاح تسجيل الدخول.

## حد الشبكة

تحقق من environment_status والسياسة الفعلية، لا من الإعداد المحفوظ وحده.
لا تعِد HTTP محجوبًا بلا تغير أو تشخيص جديد، ولا تستخدم DNS أو proxy أو TLS
بديلًا لتجاوز المنع. ظهور hostname في APK أو DNS لا يثبت عنوان API الكامل
أو هوية TEST. تحقق من هوية backend قبل mutations، وابدأ online قبل offline.

اختبارات المشرف والمطابقة تعمل دون Android SDK:

```bash
python -m pytest tests/test_runtime_probe.py tests/test_android_readiness.py
```

فحص DNS وTLS/HTTP داخل Android عند غياب curl موثق في
[مسبار الشبكة](../tools/android-network/README.md). نتائجه تشخيص بيئة مستقل
عن دفتر الوظائف: لا يُعد CONNECT403 استجابة backend ولا خطأ كلمة مرور،
ولا يكفي نجاح HTTPS لوجهة تحكم لإثبات جاهزية شبكة التطبيق.
