# خطة المعالجة وإعادة التحقق

1. **الأولوية الأولى:** إعداد نسخة إصدار موقعة بمفتاح محمي، ومقارنة بصمة الشهادة بمرجع الناشر؛ إعادة اختبار سلسلة التحديث. لا يُعاد توقيع APK محل التدقيق.
2. **الأولوية الأولى:** تضييق FileProvider إلى مجلدات مخرجات محددة؛ اختبار أن URI الممنوح لا يكشف ملفات أخرى، مع إنهاء المنح عند الحاجة.
3. **الأولوية الثانية:** تحديد backup/data extraction rules واستثناء الرموز وقواعد بيانات الأعمال؛ اختبار الاستعادة على جهاز مصرح به.
4. **الأولوية الثانية:** فصل network_security_config للتطوير، ومراجعة ضرورة صلاحيات الموقع والكاميرا والصوت والفيديو، واختبار الرفض والمنح.
5. **أُنجز للإطار:** رفض DTD/ENTITY، وإظهار أخطاء كتابة التقرير برسالة CLI مفهومة دون المساس بالملف الموجود؛ الاختبارات الجديدة تثبت الإصلاح.
6. **أُنجز للبيئة:** تحديث pip وإعادة فحص التنبيهات؛ لا تعديل لتبعيات تشغيل المشروع.
7. **فجوة معلومات:** توفير SBOM ونسخ Flutter/Dart/plugin الدقيقة لاحقًا، ومطابقتها بقاعدة ثغرات موثوقة؛ لا CVE منسوبة إلى التطبيق دون ذلك.
8. **التحقق الوظيفي:** استكمال الحالات المسجلة في E2E عند توفر runtime مستقر وحساب/خادم اختبار، مع إنشاء QA-TEST فقط وتنظيف ما أنشئ بأمان؛ لا مصادقة بديلة أو حذف بيانات موجودة.
