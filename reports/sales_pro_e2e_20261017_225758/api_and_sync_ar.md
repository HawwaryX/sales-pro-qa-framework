# API والاتصال والمزامنة

## تمييز الأدلة

1. APK: أصل HTTPS `https://sales.infinity-tech.sa` في libapp.so للمعماريات الثلاث. الإزاحات: arm64=850080؛ x86_64=850237؛ armv7=3944892. لا إعداد endpoint صريح في manifest أو ملفات assets/JSON المفحوصة؛ libapp يتضمن أسماء network.dart وbaseUrl.
2. سلاسل المسارات الفعلية تشمل `/api/v1/auth/login` و`/api/v1/auth/years` و`/api/v1/auth/company` و`/api/v1/me` و`/api/v1/customers` و`/api/v1/sync/pull` و`/api/v1/sync/push`. هذه قيم منفصلة؛ لم يُثبت تركيب URL الكامل أو معاملات الطلب، فلا تُختلق endpoints من دمجها.
3. تشغيل فعلي: أثناء تحديث القوائم رُصد طلب DNS إلى المضيف نفسه. [الأثر](evidence/runtime_dns_observed.jsonl). يربط ذلك المضيف بمحاولة التطبيق الفعلية، ولا يثبت وحده نوع الخادم أو إعداد TEST أو طلب API وصل.
4. التخزين المحلي قبل الدخول: جرد أسماء مفاتيح secure storage أظهر حالة الترحيب واللغة، ولم يظهر endpoint عام محفوظ؛ لا فك لتخزين محمي ولا نشر لقيمه. عدم رؤية مفتاح لا ينفي إعدادًا مشفرًا أو محملًا لاحقًا.
5. لم تُرصد استجابة DNS للمضيف في نافذة الالتقاط، وفشل getaddrinfo في المضيف EAI_AGAIN(-3). سجل التطبيق أظهر Failed host lookup للخطوط فقط؛ لا يثبت أن خطأ القوائم له السبب نفسه حصريًا.
6. HEAD سابق من المضيف عبر وكيل الجلسة: **CONNECT403؛ origin HTTP000؛ curl exit56؛ CONNECT tunnel failed, response403**. لا redirect من origin مثبت ولا TLS مع origin ولا HTTP401 من التطبيق. لم تُرسل بيانات الحساب بهذا الفحص.

## معنى CONNECT403

الرفض في طبقة الوكيل قبل الوصول إلى خادم الأصل، وليس رفض اسم/كلمة مرور أو دليل frontend مقابل API. البيئة الحالية restricted/enforced مع observations_current=true، والسياسة لا تشمل المضيف. المسودة المحفوظة تشمل files.fm وsales.infinity-tech.sa، لكن الحفظ لا يطبقها على هذه العملية الجارية. لم نكرر طلب HTTP المرفوض بلا تغير سياسة، ولم نستعمل DNS بديلًا أو TLS غير موثق أو ربط IP مصطنعًا.

## المصادقة وهوية TEST

أُرسل نموذج UI بالحساب النهائي المحدد: «اختر الفرع والسنة المالية.» الفرع الوحيد افتراضي والسنة غير متاحة. لا منزل مصادق عليه أو /me أو إثبات هوية حساب. لا يُحكم بخطأ كلمة المرور. ادعى المستخدم أن قاعدة البيانات TEST وأذن ببيانات مالية اختبارية، لكن مطابقة الخادم الفعلي لهذه البيئة لم تثبت؛ لم تُنفذ mutations.

## online ثم offline

| المرحلة | الحالة | الفعلي |
|---|---|---|
| وصول online للخادم | BLOCKED | DNS/سياسة الوكيل؛ القوائم لا تُحمّل |
| إدخال الحساب وتقديم النموذج | نُفذ؛ المصادقة BLOCKED | حاجز الفرع والسنة المحلي |
| أخطاء دون اتصال قبل الدخول | PASS المحدد | رسالة واضحة دون انهيار مرصود |
| إعادة شبكة المحاكي | PASS المحدد | أزيل العزل وعاد الوكيل؛ لا نجاح backend |
| عمليات أعمال online | BLOCKED | لم يفتح نموذج مصادق |
| إنشاء أعمال offline ثم sync | BLOCKED | لم يتحقق online أولًا ولا سجل اختبار |
| منع التكرار/تعارض/refresh token | BLOCKED | لا جلسة أو سجل مزامنة |

## نتيجة الاستئناف والمطلوب الفعلي

في18أكتوبر أُعيد تحديث القوائم والحساب المطابق مُعبّأ؛ لم يظهر المركز الرئيسي أو2026. لا استجابة API في logcat المفلتر ولا endpoint كامل جديد في UI. لم تكرر HEAD المحجوبة، ولم تختبر offline مجددًا.

الإعداد المقروء يتضمن قاعدة المضيف بالفعل؛ source_version للمهمة الحالية يختلف عن base_version للإعداد، والسياسة الحالية لا تحتوي القاعدة. المطلوب تشغيل التنفيذ على النسخة التي تحتويها أو إصلاح ربط/تطبيق النسخة، وليس إعادة إدخال السماح أو افتراض وجوب نشره مرة أخرى. لا أداة متاحة هنا لنقل المهمة أو إنشاء أخرى. [الأدلة والتفاصيل](resume_20261018_ar.md).

بعد وصول مشروع للخادم، تُراجع هوية TEST وتحمّل القوائم ثم يقدم الحساب نفسه بالقيم المحددة وتبدأ الأعمال online. لا يحتاج ذلك إعادة إرسال بيانات الحساب.

## تشخيص Android اللاحق

أُثبت HTTPS فعلي داخل Android عبر وكيل الجلسة وCA المناسبة للمسبار: TLS1.3 وHTTP200. DNS الافتراضي فاشل، ووجهة التطبيق ترد عند الوكيل CONNECT403 قبل TLS مع الأصل. تجربة proxy نظامي مؤقت لم تفتح القوائم، وأعيد الإعداد الأصلي. لا مصادقة أو أعمال إضافية. تشخيص البيئة منفصل:3 PASS و4 FAIL و2 BLOCKED؛الوظائف تبقى23 PASS و4 FAIL و54 BLOCKED و3 NOT RUN.
